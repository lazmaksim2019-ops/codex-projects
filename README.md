# Projects Showcase

Учебная страница «Проекты» для практического задания: список тестовых проектов, поиск, фильтрация, форма создания/редактирования и сохранение в браузере.

## Стек

- React 19
- Vite
- JavaScript / JSX
- CSS без UI-кита
- `localStorage` для сохранения данных
- Playwright + Chromium для browser smoke-тестов
- Vercel для production-деплоя из ветки `main`

## Deployment

Ветка `main` подключена к Vercel project `codex-projects` с автоматическим production-деплоем.

## Быстрый старт

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

После запуска откройте адрес Vite, обычно:

```text
http://localhost:5173
```

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск Vite-сервера для разработки |
| `npm run build` | Production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр production-сборки |
| `npm run test:browser` | Smoke-тесты в headless Chromium |

## Возможности

- адаптивная сетка карточек: 3 колонки на desktop, 2 на планшете, 1 на телефоне;
- поиск по названию, описанию, категории и статусу;
- фильтр по статусу;
- создание и редактирование проекта;
- валидация обязательных полей;
- локальные данные валидируются по схеме: повреждённые данные не ломают интерфейс;
- сохранение изменений после обновления страницы через `localStorage`;
- удаление с подтверждением;
- toast-уведомления и анимации;
- закрытие формы через `Esc`;
- адаптивный toolbar без перекрытия поиска и CTA;
- доступные подписи и `focus-visible` для основных интерактивных элементов;
- поддержка `prefers-reduced-motion`.

## Toolbar и адаптивность

Toolbar содержит только рабочие элементы: поиск, фильтр по статусу и CTA «Создать проект». Отдельного переключателя вида карточек нет — он удалён как нефункциональный элемент, чтобы в интерфейсе не оставалось кнопок без действия.

На desktop поиск, фильтр и CTA находятся в одной строке. На мобильных экранах поиск занимает отдельную строку, фильтр и CTA перестраиваются вертикально, поэтому элементы не перекрываются.

## Проверка перед сдачей

```bash
npm ci
npm run build
npm run test:browser
```

Browser-тесты проверяют:

- загрузку страницы и 5 тестовых проектов;
- безопасный fallback при некорректной структуре `localStorage`;
- создание проекта и валидацию обязательных полей;
- сохранение нового проекта после reload;
- поиск и фильтрацию;
- пустое состояние и сброс фильтров;
- desktop toolbar одной строкой;
- viewport 375 px и 320 px без горизонтального overflow;
- отсутствие пересечения поиска и кнопки «Создать проект».

## Доступность

- интерактивные элементы имеют доступные подписи;
- используется аккуратный `focus-visible` вместо тяжёлой нативной рамки;
- модальная форма поддерживает `Esc` и удерживает фокус внутри окна;
- после закрытия формы фокус возвращается на кнопку, открывшую её;
- поля с ошибками получают `aria-invalid` и связь с текстом ошибки.

## Цветовая система

Интерфейс использует одну холодную teal/navy палитру:

- `#0F766E` — основной CTA, focus и активные элементы;
- `#0D9488` — hover/градиентный акцент;
- `#115E59` — глубокий teal;
- `#0F172A` — основной текст;
- `#64748B` — вторичный текст;
- `#E2E8F0` — границы;
- `#F6F8F9` — фон страницы;
- `#CCFBF1` — мягкие активные состояния.

Оранжевый и фиолетовый не используются как конкурирующие основные акценты.

## Данные

Приложение работает без backend и использует только тестовые данные. Данные хранятся в `localStorage` под ключом `projects-showcase-data-v1`.

Для сброса демонстрационных данных можно удалить этот ключ в DevTools → Application → Local Storage и обновить страницу.

## Автор и учебный характер

Проект создан для практического задания и демонстрации frontend UX, адаптивной верстки, валидации и локального сохранения данных. Реальные пользователи, авторизация и серверная база данных намеренно не используются.
